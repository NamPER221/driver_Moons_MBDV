# Caveman Commit

## Mục tiêu

Tạo commit messages chính xác, conventional, và tối giản — không filler, không AI attribution, không self-reference.

## Format

```
<type>(<scope>): <summary>
```

- Subject line: ≤50 ký tự (hard limit 72)
- Imperative mood: "add" không phải "added", "fix" không phải "fixed"
- Không dấu chấm cuối
- Không đại từ ngôi thứ nhất (I, we)
- Không "Generated by Claude" hoặc tương tự (trừ khi project policy yêu cầu)
- Không emoji (trừ khi project convention dùng)

## Khi nào thêm body

Chỉ thêm body khi thực sự cần:
- Logic không rõ ràng từ subject
- Breaking changes (`BREAKING CHANGE:`)
- Migration steps cần thiết
- Issue references (`Closes #123`)

Bỏ qua body hoàn toàn khi subject đã tự giải thích.

## Luôn cần body

- Breaking changes
- Security fixes
- Reversions (ghi rõ cái gì được revert và tại sao)

## Ví dụ minh hoạ

**Ví dụ 1: Bug fix đơn giản**

User: "Tôi vừa fix null pointer exception trong user login"

Kết quả:
```
fix(auth): guard null user before email access
```

**Ví dụ 2: Feature mới với breaking change**

User: "Thêm JWT auth, bỏ session-based auth cũ"

Kết quả:
```
feat(auth): replace session auth with JWT

BREAKING CHANGE: session tokens no longer valid.
Clients must re-authenticate to obtain JWT.
```

## Khắc phục sự cố

**Vấn đề:** Subject line dài hơn 50 ký tự
**Cách xử lý:** Rút gọn scope hoặc bỏ scope, ưu tiên từ mô tả action chính xác nhất

**Vấn đề:** Không biết type phù hợp
**Cách xử lý:** feat/fix/chore/docs/refactor/test/perf — hỏi nếu cần context

## Output

Plain text commit message trong code block, sẵn sàng để paste. Không chạy git, không stage files, không amend commits.

## Deactivation

Nói "stop caveman-commit" hoặc "normal mode".
